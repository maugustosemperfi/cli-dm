# cli-dm — Proactive Features + Native macOS App

## Context

cli-dm today is a beautiful but passive visualization: Claude Code JSONL events flow into a dungeon/kingdom map in the browser. The backend already extracts rich signal (tool usage, errors, time gaps, costs, blockers) but never pushes any of it to the user — you have to stare at the dashboard to know anything.

Competitor baseline (researched this session):
- **Soloterm** — native Tauri macOS app; signature feature is *desktop notifications on process crashes*. Users don't have to check.
- **Conductor** — native Mac app for parallel agents, review + merge; also purely passive. No notifications.

Goal: move cli-dm from "screensaver" to "the thing that pings you when you actually need to look." Wrap it in a native macOS `.app` (full window) and use that foundation for native notifications rather than the browser's hostile permission UX. Add session digests, a read-only state API for sibling agents, and a mobile push path for away-from-desk signal.

User decisions captured (ref: AskUserQuestion in planning session):
- **Full window `.app`** (dock-occupying window with native menu).
- **REST `/api/state`**, not MCP. Upgrade later only if a real use case appears.
- **Native macOS notifications only** — skip browser Notifications API entirely. Nothing proactive ships until the `.app` does.

Additional design guidance from plan-review agent (incorporated below):
- Hub *subscription channels*, not polling `hub.eventBuffer` — lossy for burst detection and racy.
- Advisor detection extracted as a **pure function** `Detect(events, now) → []Advisory` for unit-testability.
- Dedup keys on advisor events to avoid fan-out noise when one logical failure spans agents.
- Digest generation decoupled from `FileEventStore.Close()` — three triggers (idle-timeout, Stop hook, explicit CLI command), not shutdown.
- Privacy gate (`digests.webhook_enabled: true`) on any outbound webhook.
- Drop-on-full on advisor subscription to avoid broadcast stalls (mirror slow-client drop at `internal/server/ws.go:100-103`).

## Phase 1 — Wails v2 `.app` foundation (~2–3 days)

Must ship first: native notifications can't exist without it.

**Approach:** Produce a single self-contained macOS `.app` bundle containing **both the Go backend and the React/PixiJS frontend**. No browser, no external processes, no separate install steps. Double-click → everything launches in a native window.

**How the frontend gets packaged:**
- `web/dist` (the Vite-built React + PixiJS output) is **embedded into the Go binary** at compile time via `//go:embed`. The frontend ships *inside* the `.app` bundle at `cli-dm.app/Contents/MacOS/cli-dm` and is served from memory, not from disk.
- The UI is rendered in a **native `WKWebView`** (the macOS webview component; the same rendering engine as Safari but embedded as a native widget in the app window — not a browser tab). Users do not need Safari/Chrome installed.
- The Go HTTP+WebSocket server binds to an **ephemeral loopback port** (chosen at startup, never exposed externally). The WKWebView is pointed at that port for the initial load and WebSocket connection. This is purely internal plumbing; no URL is shown to the user.
- Result: one `.app` bundle, ~10 MB, contains the Go binary, embedded frontend assets (JS/CSS/sprites/sounds), and a thin Wails runtime that provides the native window, menu, dock integration, and notification APIs.

### Tasks
- Add Wails v2 dependency (`github.com/wailsapp/wails/v2`).
- Create `cmd/cli-dm-app/main.go` (new) — Wails entry point that:
  - Embeds `web/dist` via `//go:embed all:web/dist` at package level — this is what makes the frontend ship inside the `.app`.
  - Initializes Wails app (title, window size, native menu, WKWebView).
  - Starts the existing HTTP+WebSocket server on an ephemeral loopback port (use `net.Listen("tcp", "127.0.0.1:0")` to pick a free port).
  - Points the WKWebView at `http://127.0.0.1:<port>/` for initial load — loopback only, never exposed.
  - On macOS: sets `NSHighResolutionCapable`, dock icon, bundle ID `ai.anthropic.cli-dm` in `Info.plist` (generated by Wails from `wails.json`).
- Create `wails.json` at repo root (Wails project config, icons, bundle ID, app name, version).
- Refactor static serving at `cmd/cli-dm/main.go:786` to accept an `fs.FS` so both modes share code:
  - **CLI binary (`bin/cli-dm`)**: passes a `os.DirFS("web/dist")` to serve from disk (dev-friendly; easy hot-reload).
  - **`.app` bundle (`bin/cli-dm.app`)**: passes the `//go:embed`-produced `embed.FS` so the frontend is baked in.

### Why this satisfies "convert the webapp, not just the backend"
The frontend is not just "still running on a server the user has to visit." It is:
- Compiled into the binary (`go:embed`).
- Loaded by a native macOS component (`WKWebView`), not a user-installed browser.
- Wrapped in native macOS chrome — title bar, dock icon, native menu, window traffic lights, Mission Control integration.
- Shipped as a single signable, distributable `.app` bundle alongside the Go server inside it.

From the user's perspective, it is indistinguishable from any other native macOS app: a file in `/Applications`, an icon in the dock, a window with macOS chrome. The React/PixiJS runtime is an implementation detail.

## Phase 2 — Advisor detection + native notifications + in-map UI (~3 days)

### 2a. Hub subscription + advisor core (1 day)

**Refactor the Hub** at `internal/server/ws.go:28` to support internal subscribers alongside WebSocket clients:

```go
type Hub struct {
    // existing fields...
    subscribers []chan protocol.Event  // buffered; drop-on-full
}
func (h *Hub) Subscribe(buf int) <-chan protocol.Event
func (h *Hub) Unsubscribe(ch <-chan protocol.Event)
```

Extend `Broadcast()` (`internal/server/ws.go:71`) to fan out to `subscribers` with the same drop-on-full pattern already used for slow WebSocket clients at `internal/server/ws.go:100-103`. Bump a dropped-events counter for observability.

**New package `internal/advisor/advisor.go`:**
- Pure function: `Detect(events []protocol.Event, agentStates map[string]parser.AgentState, now time.Time, cfg Config) []Advisory` — fully unit-testable with synthetic event sequences.
- `Advisory` struct: `{Class, AgentID, Message, DedupKey, Severity, Timestamp}`.
- `DedupKey = class + ":" + agent + ":" + sha1(normalized_signature)`.
- Detection rules (thresholds configurable in YAML):
  - **error_spike** — ≥3 errors on same agent in 60s window.
  - **silence** — ≥5 min with `expectingResponse=true` (extends the existing 10s JSONL-staleness check from `walking_bug.md` memory).
  - **cost_threshold** — estimated cost crosses per-session or per-hour limit (cost already estimated from token counts per `gold_cost.md` memory).
  - **repeated_error** — same normalized error message 3× consecutively for an agent.
  - **boss_defeated / blocker_resolved** — positive events; also surfaced as advisories for the "good news" channel.
- Runtime: goroutine started in `cmd/cli-dm/main.go` near the rediscovery ticker at line 862; subscribes once, maintains per-agent sliding windows, emits `advisor.*` protocol events back through `hub.Broadcast()`.
- `Mapper.SnapshotState()` (new method on `internal/mapper/claude.go:64`) — returns a deep copy of all agent state under the Mapper's mutex, safe for concurrent reads from the advisor goroutine.

### 2b. Native notification dispatcher (0.5 day)

In `cmd/cli-dm-app/main.go`, run a second subscriber that receives advisory events and triggers native macOS notifications via `wailsRuntime.Notify(title, body)`. This is a second consumer of the same subscription channel API — keep the advisor pure, the notifier I/O-only.

- Dedup at the notifier using `DedupKey`: if same key fired in last 5 min → skip.
- Global "Pause notifications for 30 min" toggle, exposed both via Wails native menu item and the in-app settings UI.
- Severity → notification style: critical (crash, cost_threshold) uses sound + banner; info (blocker_resolved, boss_defeated) uses subtle banner.
- Respect macOS Do Not Disturb by default (Wails delegates to UserNotifications.framework which already honors system Focus).

### 2c. Frontend — AdvisorBubble + settings UI (1.5 days)

**`web/src/components/DungeonMap/AdvisorBubble.ts` (new)** — mirror the SpeechBubble pattern at `web/src/components/DungeonMap/SpeechBubble.ts:1-150+`:
- PixiJS Container positioned above agent sprite (attach in `AgentSprite.ts:271-276` area where SpeechBubble is added).
- Icon + short text, dismissible on click, auto-dismiss after 10s.
- Styled per severity; red pulse for critical, blue for info.

**Event plumbing:** add `advisor.*` event types to `web/src/protocol/events.ts:189-205` (discriminated union). Handle in `web/src/stores/gameState.ts:457-1026` (`handleEvent`) — attach advisory to agent state, trigger bubble spawn.

**Settings UI:** extend `web/src/components/QuestLog/QuestLog.tsx:197-220` (VolumeControls pattern — that's already the established "settings panel"):

## Phase 3 — Session digests (~1.5 days)

Decouple digest from `FileEventStore.Close()` (which runs at shutdown, not session-end). Three real triggers:

1. **Idle-timeout watchdog** — new goroutine, 5-min tick; any session with no events for 30 min → "soft close" digest. Re-opens if activity resumes (overwrite digest). Rooted in the existing rediscovery ticker pattern at `cmd/cli-dm/main.go:862`.
2. **Stop hook received** — hook at `internal/ingestion/hooks.go:200` (`buildToolEvent`) already sees stop-type events; add a branch that calls the digest generator.
3. **CLI subcommand** — `cli-dm digest <session-id>` regenerates retroactively from stored `events.jsonl` at `~/.cli-dm/sessions/<id>/events.jsonl` (persistence already exists at `internal/storage/store.go:91`).

### Tasks
- `internal/digest/digest.go` (new):
  - `GenerateDigest(meta SessionMeta, events []protocol.Event) Digest` — **pure function** (unit-testable).
  - `WriteMarkdown(d Digest, outPath string) error` — I/O side-effect.
  - Content: agent roster + outcomes, error summary (top 5 by frequency), estimated cost, file heatmap, tool histogram, session duration, boss outcomes.
  - Output: `~/.cli-dm/digests/{YYYY-MM-DD}-{session-id}.md`.
- `internal/digest/digest_test.go` (new) — fixtures under `testdata/`.
- Config (`internal/config/config.go:19` struct addition):
  - `digests.enabled` (default `true`).
  - `digests.output_dir` (default `~/.cli-dm/digests`).
  - `digests.webhook_url` — optional.
  - `digests.webhook_enabled` — **must be explicit `true`** to activate webhook posting (privacy gate; URL presence alone is not enough).
- `internal/storage/store.go` — add `ReadAllEvents(sessionID) ([]protocol.Event, error)` helper for retroactive CLI regeneration.

### Critical files
- `internal/digest/digest.go` (new).
- `internal/digest/digest_test.go` (new) + `testdata/`.
- `internal/storage/store.go:91, 154` — leave `Close()` untouched; add events-read helper.

## Phase 4 — `/api/state` REST endpoint (~1 day)

Drop MCP per user decision. Ship simple read-only REST. Upgrade path to MCP later is trivial (thin JSON-RPC wrapper over these same endpoints).

### Endpoints
- `GET /api/state` — all agents snapshot.
- `GET /api/state?agent=<id>` — single agent.
- `GET /api/state/errors?since=<ts>` — recent errors.
- `GET /api/state/cost` — session cost summary.
- `GET /api/state/blockers` — active blockers.

### Tasks
- `internal/api/state.go` (new) — handler struct following HookReceiver pattern at `internal/ingestion/hooks.go:25-97`.
- Mount at `cmd/cli-dm/main.go:773-780` alongside `mux.Handle("/api/hooks", hookReceiver)`.
- Auth: reuse `checkAuth` from `internal/ingestion/hooks.go:347` with the same `hooks_auth` token.
- Reads from `Mapper.SnapshotState()` (Phase 2) — no direct buffer access; keeps concurrency clean.

### Use case
Child Claude Code agents (sub-agents, siblings) can `curl http://localhost:8420/api/state?agent=<sibling-id>` to see what another agent is doing, find active blockers, or check the error count before retrying. cli-dm becomes a thin coordination surface for multi-agent workflows.

### Critical files
- `internal/api/state.go` (new).
- `internal/api/state_test.go` (new) — table-driven handler tests.
- `cmd/cli-dm/main.go:773-780` — route registration.
